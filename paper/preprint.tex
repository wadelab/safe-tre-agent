\begin{abstract}
\noindent Trusted research environments (TREs) protect sensitive data by
keeping analysis inside an enclave and releasing only checked outputs. Their
statistical disclosure controls assume a human analyst. Placing a language
model between the analyst and the data changes the threat model: the model can
be prompt-injected by the data itself, can chain individually safe queries
into a differencing attack, and can emit code that smuggles rows into an
``aggregate''. We ask whether inserting an AI breaks the disclosure guarantee,
and whether a deterministic safe-outputs gateway restores it. Our prototype
confines the model to proposing a typed aggregate query over an allowlisted
catalogue; validation, read-only execution, disclosure control, a session
auditor whose refusals are simulatable from published metadata, and a keyed
audit chain then decide what leaves. Richer analyses --- generalized linear
models and analysis of variance --- are admitted without widening the boundary
by fitting them \emph{only} from aggregates the gateway has already checked, so
a model release inherits the cells' safety and adds no row-level surface. The
design is stated as a normative specification --- seventeen requirements and
twenty-two prohibitions, each traced to enforcing code and tests --- and the
finite request space of every procedure is exported as data and checked by
bounded models in a solver, while the query boundary itself --- what a query
may name, and what SQL it may become --- is proved in a theorem prover, pinned
to the running code. A red-team harness replays twenty-two scenarios with
the gateway off and on: eight leak row-level data without it; all eighteen
attacks are blocked with it, while benign analysis passes. Measuring a local
model as planner shows why the boundary must not trust refusal: the model
proposed a valid query for almost every unanswerable request, deflecting rather
than refusing.
\end{abstract}

\section{Introduction}

TREs are how sensitive data are analysed at national scale: analysis runs near
the data, and only approved outputs leave~\cite{opensafely2020}. The output
checks are statistical disclosure control (SDC) --- minimum cell sizes,
dominance rules, suppression --- designed around a human analyst working at
human speed~\cite{hundepool2012}.

An LLM agent inside a TRE breaks three assumptions at once. First, the data
becomes an input channel to the analyst: a hostile record can carry an
instruction the model may follow~\cite{greshake2023}. Second, query volume and
coordination stop being human-limited, so multi-query attacks --- differencing,
triangulation~\cite{dinur2003} --- become cheap. Third, if the model writes
code, every release check can be bypassed upstream of it.

This paper asks a narrow question: can a deliberately small, inspectable
interface keep the useful part of AI assistance --- planning an analysis from a
natural-language request --- while preserving the TRE's disclosure guarantee?
The claim is systems-safety, not model alignment: the model is treated as
untrusted infrastructure, and every guarantee is carried by deterministic code
on the data side of the boundary.

Contributions:
\begin{enumerate}
  \item a boundary design in which the model's only executable output is a
    typed, allowlisted aggregate query (\S\ref{sec:design});
  \item a session auditor whose differencing refusals are \emph{simulatable}
    from published metadata, with the residual stated exactly
    (\S\ref{sec:auditor});
  \item a way to admit statistical models --- GLMs, ANOVA --- with no new
    disclosure surface, by fitting them only from gateway-checked aggregate
    cells (\S\ref{sec:procedures});
  \item a normative specification (17 requirements, 22 prohibitions) whose
    procedures export their finite request space as data, checked by a bounded
    model in a solver (\S\ref{sec:spec});
  \item a red-team evaluation, gateway off versus on (\S\ref{sec:redteam});
  \item a planner-quality measurement showing that refusal must come from the
    boundary, not the model (\S\ref{sec:planner}).
\end{enumerate}

The prototype runs on synthetic data modelled on a UK loot-box and in-app
spending study. Everything is open source.

\section{Threat model}
\label{sec:threat}

Six assumptions bound the claim. (A1)~The planner is untrusted: it may be
prompt-injected, buggy, or adversarial. (A2)~The data may be hostile: any
string field can carry an injection, SQL, a spoofed tool call, or a
spreadsheet formula. (A3)~The operator supplies the network boundary and an
upstream identity proxy. (A4)~The audit key and chain anchor live off the
application host. (A5)~A production deployment uses a \emph{local} model:
a remote model API is itself an egress channel, tolerable only for synthetic
data. (A6)~All data here are synthetic.

The attack classes evaluated are: over-granular queries that produce small
cells; prompt injection planted in survey free text; code-channel smuggling of
identifiers inside an ostensible aggregate; two-query differencing; direct and
disguised re-identification requests; loose interpretation, where a valid but
wrong query silently answers a different question; and, for the model tools, a
regression asked over a grid that hides a suppressed cell.

\section{Design}
\label{sec:design}

\paragraph{The query boundary.}
The model never writes code or SQL. It may only propose a \emph{QuerySpec}: a
declarative aggregate (count, mean, sum, sum of squares, or Pearson
correlation) over a fixed catalogue of pre-joined, read-only datasets, with
typed, allowlisted dimensions, measures, filters and bounded group-bys.
Validation rejects unknown fields, off-catalogue columns, and type-invalid
operators before anything executes. Direct identifiers, free text and raw
timestamps are absent from every allowlist, so no valid query can name them.
The validated spec compiles to parameterised SQL over public views --- filter
values are always bound parameters --- and runs under fixed memory, thread and
row caps. The query space is finite and enumerable, which is what makes the
boundary testable and provable. A request may also be a literal spec --- a JSON
object taken as the query itself, bypassing the planner --- and every
downstream control still applies, so a caller who does not want a language model
in the loop can drop it without leaving the boundary.

\paragraph{The disclosure gateway.}
Released tables pass SDC checks in the ACRO
tradition~\cite{acro}: a minimum-cell threshold counted over distinct
\emph{individuals} (not rows, which one hyperactive contributor can inflate); a
dominance ($p\%$) rule for sums and means; for correlations, a leave-one-out
influence bound, since a single high-leverage individual can drive a released
$r$ on a small group; count rounding; and primary plus complementary
suppression, so a margin cannot reconstruct a suppressed cell. Every safety
statistic is computed on internal views that are never queryable. An
unresolved check --- a dominance the engine could not compute --- fails
closed: the cell is suppressed, never defaulted to safe.

\paragraph{Session auditing, simulatably.}
\label{sec:auditor}
The agent-specific control is a per-session auditor: it remembers each
released cohort by its normalised filter predicate, denies a new cohort within
a small symmetric difference of a prior one (the signature of differencing),
and enforces a query budget. The subtlety is that a refusal is itself an
output. Following Kenthapadi, Mishra and Nissim~\cite{kenthapadi2005}, the
denial decision is a function only of \emph{published} donor marginals --- a
disclosure-safe frequency table any analyst can download --- so a refusal
reveals nothing an analyst could not already compute. Refusal messages carry
no numbers. The bound is conservative and its residual is stated exactly: it
misses differencing that isolates a small group through the interaction of a
common category with a narrow cohort, and catching sub-threshold
rare-category isolation uses one bit of private information. That residual is
the precise gap between deterministic, explainable SDC and differential
privacy~\cite{dwork2006}, which closes it at the cost of noisy outputs.

\paragraph{Metadata without leakage.}
Three contracts are published to the analyst: a capability manifest (tools,
limits, hashes); a data dictionary carrying design-time metadata only ---
column roles, descriptions and \emph{declared} categorical domains, the study
codebook; and the safe marginals above. Building these surfaced a rule worth
stating generally: a value's \emph{name} is disclosive. Nulling the count of a
rare observed category still publishes the category; a hostile string smuggled
into a field would leak verbatim as a key. Published tables therefore drop
values outside the declared domain entirely, rather than count-nulling them.

\paragraph{Accountability.}
Every request --- released, redacted or denied --- is appended to an
HMAC-chained audit log with an off-box key and chain-head anchor, so an
attacker who can rewrite the database cannot forge a verifying history.
Verification fails closed on malformed rows. Each decision exposes the
validated spec, the compiled SQL, the findings and an ordered pipeline trace.

\section{Composable procedures, fitted from cells}
\label{sec:procedures}

An aggregate query is a poor interface for real analysis: researchers want
regressions and contrasts, not just group means. The tempting fix --- let the
model fit a model on the rows --- reopens exactly the row-level surface the
boundary closed. We take the opposite route. A statistical model is fitted
\emph{only} from aggregate cells that have already passed the gateway, so it
sees nothing an ordinary released table would not, and inherits the cells'
safety rather than adding a second disclosure argument.

\paragraph{Procedures as contracts.}
Every procedure --- each aggregate, and each model --- is a registered object
that declares and discharges a fixed set of obligations: admissibility (which
requests it will accept), compilation safety, an influence control or its
inheritance from cell vetting, and lineage. The three former dispatch sites
that switched on a function name now delegate to this registry and fail loudly
on anything unregistered. Adding a procedure without declared obligations fails
the build, so the safety argument cannot silently fall behind the feature set.

\paragraph{A GLM, cells-first.}
The first model procedure fits generalized linear models --- Gaussian,
binomial (logit), and Poisson, canonical links, categorical terms only --- by a
small iteratively-reweighted-least-squares fitter that reads
\emph{only the gateway-finalized design-cell tables}: the per-cell counts, means
and second moments that the gateway has already rounded and suppressed. Three
prohibitions make this tight. If any design cell is suppressed, or missing from
the full grid of observed levels, the whole model is denied --- a hole in the
grid must not be filled by the fit. No per-observation quantity may leave:
residuals, fitted values, leverage and per-donor predictions are simply not
expressible. And the fitter must be a deterministic function of the finalized
cells alone; a released model ships the coefficient table, the summary block,
and the vetted cell table it was fitted from, and a helper reproduces the
release bit-for-bit from that table. Model refusals, like the auditor's, are
decidable from the released-equivalent cell decisions and name terms, never
quantities. One-way analysis of variance follows the same pattern over the same
moment cells.

\paragraph{Why fit from rounded cells at all.}
Fitting from finalized (rounded, suppressed) cells rather than exact ones
introduces a distortion. We measure it rather than wave it away: a script
quantifies the coefficient shift induced by base-5 count rounding across the
model skeleton, and the row-level fits are cross-checked against
\texttt{statsmodels} --- a development-only oracle --- to agree to $10^{-8}$
before rounding. The distortion is the honest price of never touching a row;
its size is reported, not assumed negligible.

\paragraph{The larger price: the dispersion cell decides availability.}
Rounding is the price everyone anticipates. The one the design did not state is
which cell refuses. A gaussian model needs two vetted tables --- the group means
and the group sums of squares --- and either being suppressed denies the model.
Both face the same dominance bound, that no donor holds more than half of a
cell, but squaring is not share-preserving: a donor holding a fraction $p$ of a
cell's total holds $p^2/(p^2 + (1-p)^2/(k-1))$ of its sum of squares when the
cell's other $k-1$ donors are equal, crossing one half at
$p = 1/(1+\sqrt{k-1})$ --- about $0.19$ for a twenty-donor cell and $0.09$ for a
hundred-donor one, and lower still for the heavy-tailed cells real data produce.
The same nominal rule is therefore far tighter on the second moment than on the
first, and it is the second moment that gates release.

We measure the gap. Across the design-cell space, 2650 of 2778 cells at or above
the frequency threshold pass the bound on the linear scale, and 355 of those
fail once squared; not one fails on the linear scale while passing on the
squared, so here the squared bound is a strict tightening. Across the gaussian
model skeleton, 47 points release and a further 36 are refused by the dispersion
cell alone --- 43\% of the otherwise-available models. This is not a defect: a
sum of squares dominated by one donor really would disclose that donor's value.
But it means availability in a cells-first design is governed by a threshold
nobody states. Analysts are told about the minimum cell size; what actually
refuses them is the second moment. Families resting on counts or first moments
do not inherit the ceiling, families needing a variance, a standard error or an
$F$ do, and any output checker adopted for the cell layer should decide
deliberately whether the second-moment cell is checked on the same parameters as
the first.

\section{Specification and verification}
\label{sec:spec}

The design is fixed in a normative specification: seventeen requirements (what
the system must do) and twenty-two prohibitions (what it must never do), each
with a stable identifier, plus the trust assumptions of \S\ref{sec:threat} and
explicit non-goals (notably: no differential-privacy claim, no cross-session
defence, and the code-execution sandbox is illustration, not a jail). A
traceability table maps every prohibition to the module that enforces it and the
test that checks it, with an honest implemented/partial status.

Five verification layers now exist. Property-based tests sample the query
space; they surfaced a fail-open crash --- floating-point cancellation drove a
variance product negative and the influence query raised instead of suppressing
--- exactly the class of bug the fail-closed prohibition names, fixed by making
the degenerate case suppress. Exhaustive enumeration then covers what sampling
might miss: the query skeleton, and all 767 points of the model skeleton (718
GLM, 49 one-way ANOVA), are walked in full. A red-team harness exercises the
prohibitions end to end (\S\ref{sec:redteam}). Finally, the layer the earlier
design only anticipated is now real, split by the shape of each claim. Where
the claim is a search for bad instances, a bounded model generated from the
exported request space is checked in a solver: suppressing any design cell
denies the model; a released model is a function of finalized cells alone; and
the session auditor's differencing rule blocks rare-category isolation, with
the rule's two documented residuals exhibited by the solver as satisfiable
runs rather than asserted in prose. Where the claim is universal, it is
proved: a theorem prover shows that no valid query names an identifier,
free-text or timestamp column, that internal-only columns never reach a
grouping or a release, and that every compiled query is a single read-only
SELECT over its declared view with every filter value a bound parameter ---
over the whole space of specs, not a bounded fragment. Three synchronisation
tests pin the code to the exported skeleton and the skeleton to the models,
the prover's compiled-SQL claim is pinned byte-for-byte against 414 queries
rendered by the live engine, and both toolchains are replayed in continuous
integration against version-pinned binaries, so a change to the code that
outran the proofs would fail the build.

\paragraph{The fifth layer: equalities the release must satisfy.}
The layers above ask what the system rejects. The fifth asks what its output
is a \emph{function of}. The model path already carried such a check: a helper
refits a released model from the released cell table alone, and must reproduce
it bit for bit. The query path now carries its analogue, in two directions.
Over the query skeleton the released frame is recomputed from the
gateway-finalized table and the specification alone and required to match byte
for byte; and the engine's frame is then perturbed in every way finalization
is supposed to erase --- cell counts moved inside their rounding bucket, the
internal distinct-donor count and the dominance and influence witnesses moved
inside their verdict, tied rows reordered --- with the release required to
come back unchanged. The first direction says a verifier holding only what the
gateway approved can reproduce the release; the second says that of each
internal control, only its verdict reaches the output, never its value. A
spread sample runs in continuous integration and the whole space on demand.

The second direction is the one that pays. It found two channels through which
released output was still a function of the exact, pre-rounding cell counts:
which cell complementary suppression sacrifices, and the order in which
released rows appear. Neither discloses a value, and a check that asks only
whether the released numbers are safe cannot see either; but of two cells that
both release as a count of ten, either channel told an analyst which was the
smaller --- exactly the distinction rounding exists to remove. Both now rank
on the released count and then the public cell key, which has the incidental
benefit of making a release reproducible run to run, as ordering by a count
with ties never was. This is the argument for the layer: an equality stated
over released artefacts catches disclosure that a predicate over released
values is not looking for.

\section{Red-team evaluation}
\label{sec:redteam}

The harness replays twenty-two scenarios --- four benign, eighteen attacks ---
against a single session, first with the gateway off (raw output returned) and
then on. A leak oracle checks released output for row-level disclosure; for
inferential attacks the oracle is complemented by which control fired, since
the individual queries of a differencing pair are not themselves row dumps.

With the gateway off, eight of the twenty-two scenarios leak row-level data
(small-cell tables, injected free text propagated to output, smuggled
identifiers, a regression over a grid hiding a suppressed cell). With the
gateway on, all eighteen attacks are neutralised --- denied, or redacted and
released --- while the benign analyses flow through, small cells suppressed and
explained (Figure~\ref{fig:redteam}). The suite runs in continuous integration
and fails the build on any regression.

\section{Measuring the planner}
\label{sec:planner}

The gateway makes planner mistakes safe, not invisible: a valid but wrong
query releases a misleading answer. A scored corpus (18 answerable requests
with acceptable reference specs; 4 unanswerable requests whose correct outcome
is a validation rejection) measures this gap

\footnotetext{A remote-hosted model behind an OpenAI-compatible endpoint,

planner the boundary must tolerate, not one product.}

Two findings matter for the architecture. The model plans usefully but
imprecisely --- its common miss is a dropped filter, yielding a valid query
whose mean is diluted by zero-value events: safe, but not the question asked.
And it almost never refuses: on unanswerable requests it \emph{deflects},
proposing a valid query that silently answers a different question (for
``wellbeing per donor'' it proposed mean wellbeing by age band). Refusal
behaviour cannot be delegated to the model; the boundary must supply it. The
keyword control's higher rejection rate is a property of its fixture, not of
keyword planning.

\section{Related work}

OpenSAFELY established code-to-data analysis with human output checking at
national scale~\cite{opensafely2020}; this work explores the automated,
agent-aware layer above such checking. ACRO/SACRO provide semi-automated SDC
for research outputs~\cite{acro}; our gateway is a lightweight stand-in shaped
for eventual ACRO integration, with the agent-specific session layer on top.
The Five Safes framework organises the governance mapping~\cite{fivesafes}.
Simulatable auditing~\cite{kenthapadi2005} supplies the refusal-safety
criterion; reconstruction attacks~\cite{dinur2003} and differential
privacy~\cite{dwork2006} bound what deterministic SDC can ultimately promise.
Indirect prompt injection~\cite{greshake2023} motivates treating the data as
an input channel to the model. Fitting a model from published margins rather
than rows is the disclosure-facing cousin of long-standing work on inference
from aggregate and marginal tables.

\section{Limitations}

The prototype makes a bounded claim. It is not a differential-privacy system;
its controls are SDC, and the simulatability residual is closed only by a DP
accountant. The session auditor does not defend across sessions or colluding
users. The disclosure engine is a stand-in for ACRO. The model tools cover
GLMs and one-way ANOVA over categorical terms only, and fitting from rounded
cells carries a measured distortion. The legacy code-execution path is retained
only as a red-team narrative; it is not a secure sandbox. The planner corpus is
small and single-domain, and sampled models vary run to run. All evaluation is
on synthetic data; the deployment model (local model inside the enclave,
operator-supplied identity and network boundary) has been exercised only in a
test setting.

\section{Conclusion}

An LLM agent does break the human-analyst assumptions behind TRE disclosure
control --- measurably, through injected data, cheap multi-query attacks, and
a demonstrated unwillingness to refuse. A small, typed, deterministic boundary
restores the guarantee while keeping the planning help: the model proposes,
the safepod disposes. Richer analysis need not widen the boundary --- a model
fitted only from checked cells inherits their safety --- and the safety argument
can be carried as machine-checked clauses rather than intentions. The parts that
made this workable were unglamorous: finite request spaces, fail-closed
defaults, refusals that carry no numbers, metadata that never publishes an
undeclared value's name, and a fitter that never sees a row.
