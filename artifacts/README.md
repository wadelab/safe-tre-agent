# Artifacts

Two unrelated kinds of thing share this directory: **measurements**, which are
small, tracked, and cited as evidence by the specification and the decision
records; and **presentation material**, which is large, mostly untracked, and
regenerated on demand.

## Measurements (tracked)

Each `.json` here is the output of a `scripts/measure_*.py` run and is the
evidence some parameter or decision rests on. They are committed because a
claim of the form "measured, it costs 5%" is worth nothing without the
numbers, and a decision record that cites an artifact nobody can open is a
decision record nobody can check. Regenerate a file by rerunning its script;
the numbers move with the code and the dataset, so a stale one is a bug.

| File | Generated by | Evidence for |
|---|---|---|
| `composite_cost.json` | `measure_composite_cost.py` | what composing an external checker costs — 23 more suppressed cells of 4684, 5 of 102 gaussian models ([D6](../docs/decisions/D6-checker-default.md), `vetter`) |
| `dispersion_sensitivity.json` | `measure_dispersion_sensitivity.py` | how many gaussian models lose their standard errors at a given second-moment bound ([D3](../docs/decisions/D3-second-moment-parameters.md), [D4](../docs/decisions/D4-robust-dispersion.md), `moment2_dom_threshold`) |
| `rounding_distortion.json` | `measure_rounding_distortion.py` | what rounding to base 5 does to a released value (`round_base`) |
| `timing_channel_standin.json`, `timing_channel_external.json` | `measure_timing_channel.py` | the response-time channel at the gateway, with and without a checker: latency tracks cohort size at Spearman +0.86 ([D5](../docs/decisions/D5-timing-channel.md)) |
| `timing_channel_web_unpadded.json`, `timing_channel_padded.json` | `measure_timing_channel.py --through-web` | the same channel at the HTTP boundary, before and after quantisation: orderable sub-threshold pairs 7 of 15 → 0 of 15 (`response_quantum_ms`) |

Every one of these is cited by a parameter's `evidence` field, a decision
record's `evidence` list, or both — and `tests/test_policy_catalogue.py` and
`tests/test_decision_log.py` each check that a cited file exists. Deleting one
breaks the build rather than quietly unmooring a number from what produced it.

## Presentation material

The full slide decks and the rendered user guide live here on disk but are
**not tracked in git** (each deck revision added ~450 KB of undiffable binary
to the history); distribute them as GitHub Release assets instead. Three small
plain-language explainers are the deliberate exceptions and ARE committed:
`ELIF.ppt`, `ELIF-FORMAL.ppt` and `GUIDELINES.ppt`.

## The overview deck is generated

`safe-tre-agent-overview.pptx` is built by `scripts/make_decks.py` from the
current project state and live screenshots — the generator is the source of
truth, the `.pptx` is a disposable output:

```bash
scripts/restart_web.sh                                   # serve the app
uv run --group decks python scripts/make_decks.py        # capture + build
```

Screenshots land in `artifacts/shots/` (also gitignored); pass `--no-capture`
to rebuild from existing ones. Regenerate after any UI or status change so the
deck never drifts from the interface.

## The component map is generated

`safe-tre-agent-components.pptx` — the component & trust map (runtime
pipeline, assurance toolchain, upstream-project provenance) — is built by
`scripts/make_component_map.py`. No screenshots, so no capture step; the
red-team corpus size is read from `redteam/attacks.yaml` at build time:

```bash
uv run --group decks python scripts/make_component_map.py
```

Regenerate after adding a procedure, a formal model, a CI job, or a runtime
dependency, so the map never drifts from the code.
